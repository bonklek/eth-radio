Publish safely

Prepare bounded local media publication without treating a prototype workflow as a production broadcast service.

The repository contains local segmentation and publication utilities, but this is not a release-ready public command guide. Do not fund, deploy, or sign based on this page alone.

Before you start

  1. Start on Sepolia. Mainnet requires explicit confirmation in the current local tooling and can spend real funds.
  2. Use a new, dedicated low-value publishing wallet. Keep its private key only in local secret storage; never paste it into a browser, URL, issue, screenshot, or repository file.
  3. Independently verify the chain, Station address/deployment, wallet address, and RPC behavior before any signature.
  4. Set a maximum total exposure and a per-publication limit before preparing media. Stop when either limit is reached; do not rely on a future reimbursement.

Local-file workflow EXPERIMENTAL

Generated media, manifests, work directories, private endpoints, wallet state, and keys are operator-local. Do not publish them as part of a source archive or static site. A viewer cannot prove that a local publisher continues to run after a segment is observed.

Fees, budgets, and capacity

EXPERIMENTAL The fee-estimate schema distinguishes base, guarded, and stress planning scenarios. A stress estimate is a planning input for publisher liquidity—not a fixed cost, fee ceiling, escrow, capacity reservation, inclusion guarantee, Station subsidy, or reimbursement claim.

Keep separateWhy
Expected cost and maximum exposureExpected cost can change before inclusion; maximum exposure is the publisher’s own stopping boundary.
Publisher liquidity and expected reimbursementLiquidity must cover publication first. An expected reimbursement cannot fund a transaction.
Station subsidy and assigned fundingNo current public fee-policy contract assigns or guarantees a subsidy.
Blob availability and publication successA successfully included transaction does not guarantee later provider retrieval or viewer playback.

Pause, stop, and recovery

For any uncertain condition—fee spike, insufficient liquidity, failed endpoint, local encoding failure, machine shutdown risk, unknown Station state, or a transaction that has not reached the confirmation depth you require—stop new submissions and reconcile the chain before resuming. Do not assume closing a GUI, browser, or terminal has the same effect as stopping a publisher; exact supervisor behavior requires a separately reviewed public release.

Live input boundary PLANNED / EXPERIMENTAL

Live capture, OBS, webcam, desktop, playlist, and looping input are not a reliable public broadcast service. A live input cannot be completely preprocessed: it needs parallel capture, encoding, segmentation, and publication with a bounded lead. Any overlay carrying a block hash, UTC estimate, or segment number is advisory liveness evidence, not a reason to reject otherwise valid media when it becomes stale.

Do not proceed when

  • You cannot identify the exact chain, Station, and funded publisher address.
  • The key or endpoint would need to be shared with a browser, screenshot, archive, or third party.
  • The fee estimate is expired, unverified, or higher than your exposure limit.
  • You are relying on an unassigned subsidy, a future claim, or a name binding to cover current wallet liquidity.
  • You need a production uptime, delivery, or reimbursement guarantee.
