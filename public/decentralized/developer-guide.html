V1 contract evidence SHIPPED & VERIFIED

Station.publishSegment accepts a stream ID, sequence, duration, payload length/hash, codec, previous segment hash, and blob count. It rejects zero blobs, more than six blobs, duplicate publisher/stream-hash/sequence tuples, and missing blob hashes. It emits SegmentPublished with indexed publisher, stream ID hash, and sequence.

Viewer integration rules

  1. Read Station logs with a verified chain ID and exact Station address.
  2. Sort by sequence, block number, transaction index, and log index; do not rely on provider order.
  3. Require an explicit publisher when a stream ID is ambiguous.
  4. Retrieve sidecars from a beacon endpoint, match versioned hashes, reconstruct bounded payload bytes, and verify the payload hash before playback.
  5. Make scans and handlers replay-safe: logs can repeat, endpoints can disagree, and recent chain state can reorganize.

Capabilities and compatibility EXPERIMENTAL

The shared protocol package has versioned identifier, availability, playback-decision, and constitution schemas. These are not wired into the public watcher as canonical V2 behavior. An integration encountering an unsupported version, invalid schema, conflicting identity evidence, or unknown capability must show that condition and decline to infer a safe default.

Fees, fallback, and policy PLANNED / EXPERIMENTAL

Fee snapshots are deterministic client planning evidence, not an oracle, enforceable policy, reimbursement liability, or capacity reservation. The bounded fallback resolver is experimental schema logic and does not make the V1 watcher a Station V2 fallback client. Do not fabricate an ABI, module interface, auction rule, vault claim, or name-resolution API from these sources.

Security review checklist

  • Validate all RPC/beacon/media input sizes and types; render metadata as text, never trusted HTML.
  • Verify contract deployment and chain context before a user signs or funds anything.
  • Keep private keys and API credentials outside browser-delivered configuration.
  • Model reorg/finality, endpoint divergence, and blob/media availability as normal failure cases.
  • Use released fixtures and public source evidence before publishing copyable commands.
