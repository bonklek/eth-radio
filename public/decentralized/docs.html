Overview

Radio Free Ethereum is an Ethereum blob-radio prototype. A publisher submits media segment metadata to a Station contract and supplies blob versioned hashes in the transaction; the browser watcher reads Station logs from an execution RPC, retrieves matching blob sidecars from a beacon endpoint, verifies and reconstructs the payload, then plays verified segments. A Station V1 channel is scoped by the Station contract, publisher address, and stream ID—not by a stream name alone.

Ethereum blocks are not a wall-clock scheduler. The watcher can display UTC estimates, but block inclusion, RPC availability, blob serving, and a local publisher’s uptime remain external reliability boundaries.

Quick start: viewers SHIPPED & VERIFIED

  1. Open the watcher and choose ETH (mainnet) or SEP (Sepolia).
  2. Enter a Station contract/deployment transaction in Archive, or use a trusted share URL containing Station, publisher, and stream information.
  3. Wait for the watcher to find and verify segments. It remains idle when no recent verified signal is available.
  4. Use the status and endpoint details before assuming playback is live. A segment can be recent yet unavailable from the selected RPC or beacon provider.

Recovery: if a stream stalls, refresh first; then check the execution and beacon endpoint health in Settings. Paste an exact transaction, block, or blob reference into segment lookup when discovery is incomplete. A raw stream name without a publisher is ambiguous; select a publisher-specific archive/favorite or an exact Station transaction instead.

What indicators mean: the current V1 watcher verifies segment metadata and payload before playback. It does not implement canonical Station V2 scheduling, `.gwei` resolution, a live-proof signal, or a contract-backed fallback policy. Treat a loaded segment as verified media evidence, not a guarantee that a broadcaster is currently live.

Publishing EXPERIMENTAL

The public repository includes local tools for segmenting media and publishing blob-backed segments. Before funding or signing, use a dedicated low-value publishing wallet, begin on Sepolia, set a total spending limit, and independently verify the Station deployment, chain, RPC endpoint, and media input. Do not place a seed phrase or private key in a command, URL, browser field, screenshot, or issue.

Local-file and live-input operation are prototype workflows. A local machine, encoder, network connection, wallet, and endpoint availability can each stop a stream. Closing a viewer does not prove a publisher remains active. This documentation intentionally does not provide copyable funding or deployment commands because public release-ready command interfaces have not been verified here.

Conceptual live pipeline (planned/experimental): capture → encode → segment → optional liveness overlay → blob publication → Station indexing → viewer buffering/playback. Live feeds cannot be fully preprocessed: segmentation and publication must progress in parallel with a bounded preparation lead. A block hash, UTC estimate, or segment number burned into media is advisory evidence; stale witness data should be labeled rather than used to reject media automatically.

Identity, scheduling, and fallback PLANNED

`.gwei` is a proposed discovery and presentation layer, not the economic identity of a Station, channel, vault, claim, or reservation. Direct Station and channel identities remain the recovery path whenever name resolution is missing, stale, conflicting, unsupported, or unverified. No current public watcher resolves `.gwei` names.

Station V2 identifiers, block-range seasons, airtime allocation, vault claims, advertisements, scheduled replay, and standing fallback are not deployed V1 features. The shared protocol package contains partial, versioned experimental schemas: its fallback resolver uses bounded concrete candidates and never treats fallback as proof of a live primary. A scheduled replay would still require a prior assignment; transactionless standing fallback is a client playback choice, not an airtime reservation.

Fees and availability EXPERIMENTAL

Client fee snapshots are planning evidence only. They distinguish base, guarded, and stress estimates and keep publisher liquidity, Station subsidy, and maximum reimbursement separate. A forecast is not an oracle, hard fee maximum, escrow, capacity reservation, inclusion guarantee, subsidy assignment, or reimbursement promise. Higher fees, failed inclusion, or unavailable blobs remain possible.

Blob availability is provider-dependent and time-bounded. The experimental availability profile can calculate a conservative theoretical window from explicit profile data; it never guarantees that a provider will serve media. Use fallback endpoints, reduce segment density, top up a dedicated wallet only after review, or stop safely when a configured exposure limit is reached.

Developer map SHIPPED & VERIFIED

  • contracts/Station.sol: V1 Station contract. publishSegment rejects zero or over-six blobs and duplicate publisher/stream/sequence tuples, then emits SegmentPublished.
  • public/decentralized/: browser-only watcher. It reads execution logs and beacon blob sidecars directly; endpoint CORS support is required.
  • packages/protocol/: partial shared schemas for canonical V2 identifiers, availability, bounded fallback decisions, and constitution snapshots. These are not a deployed V2 ABI.
  • packages/economics/: deterministic client-side fee-estimate snapshots, explicitly labeled planning-only.

Pseudocode, proposed schemas, and fixtures are not production contract interfaces. Integrations should validate chain ID, Station address, publisher scope, ordering fields, hashes, version support, and reorg/finality state before acting. Make handlers idempotent: logs can be replayed, reorganized, or fetched from disagreeing providers.

Security and trust model

Media, metadata, RPC responses, gateways, and browser state are untrusted inputs. Verify the chain, Station, publisher, stream scope, transaction, and segment generation before trusting a share or signing. Do not inject metadata as HTML. Browser extensions, compromised endpoints, reorgs, unsupported protocol profiles, and fee-estimation uncertainty can change what a user observes.

Mainnet is high risk. Test on Sepolia first with fictional or low-value example identities, a dedicated funded wallet, explicit per-transaction and total-exposure limits, and a recovery plan. Never assume a name rebinding, policy change, or tombstone moves balances or history.

Glossary

Station
A contract that records V1 segment publication events.
Channel
For V1, a publisher-scoped stream within a Station; V2 channel IDs are experimental schemas.
Segment / Blob
A bounded media unit and the blob data referenced by its transaction.
Scheduled replay / standing fallback
Planned distinct modes: the former is assigned playback; the latter is a client-side choice.
Canonical plan / observed selection
Planned separation between chain-backed intent and what a client actually found playable.
Publication floor / inclusion feasibility
Proposed policy concepts; neither is guaranteed by a client estimate.
